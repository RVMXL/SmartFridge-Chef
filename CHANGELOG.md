# Changelog

Формат — в духе [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/);
версии — по [SemVer](https://semver.org/lang/ru/). Разработка идёт поэтапно
по ТЗ: каждый шаг = отдельная версия и отдельная миграция схемы БД.

## [0.6.6] — 2026-10-30

Ремонт доступа к технике: репорт владельца «не могу поменять
оборудование в приложении — нет вкладки». Редактор техники существовал
с v0.6.4, но жил в самом низу длинного экрана «Профиль питания» (после
калоража, БЖУ, диет, аллергенов, столов Певзнера и нелюбимых продуктов)
и не находился.

- **Настройки → «Техника на кухне»** — отдельная плитка в разделе
  «Профиль питания»: подзаголовок показывает текущий список (или
  «Вся техника есть» для профилей до v0.6.4, «Ничего не выбрано —
  работают замены» для пустого), тап открывает компактный экран с теми
  же чипами; сохраняется только поле `equipment`, остальные поля
  профиля не затрагиваются.
- **kAppVersion 0.6.4 → 0.6.5** (хотфикс ea77de7): релизный коммит
  v0.6.5 поднял версию в pubspec, но не константу — VER-1 держал CI
  красным три прогона, собранная v0.6.5 показывала в приложении
  «0.6.4».

## [0.6.5] — 2026-10-29

Ясность шагов: техника называется явно («на чём» и «как»). Продолжение
репортов владельца к v0.6.4: (1) шаг панкейков «Выпекайте маленькие
панкейки…» не называл технику и читался как «только в духовке» — на деле
это жарка на сковороде; (2) «прогрейте» в супах/пастах/соусах так же
невнятно, как было в кашах — не сказано, что греть, на чём и как.

### Исправлено

- **Панкейки (r0001)**: «Выпекайте…» → «Обжаривайте маленькие панкейки
  на разогретой сковороде с маслом по 1–2 минуты с каждой стороны».
  Духовка для панкейков не нужна — сбивающая формулировка убрана;
- **«Прогрейте» → явные действия** (41 шаг с ru/en-зеркалами):
  супы (7 шт.) — «Поварите ещё 3–5 минут в кастрюле на слабом огне»;
  куриный суп — «Поварите всё вместе в кастрюле ещё 5 минут»;
  бефстроганов — «Соедините всё в сковороде… тушите 5 минут»;
  макароны по-флотски — «Добавьте макароны в сковороду к фаршу…»;
  пасты (14 шт.) — «Обжарьте основу на сковороде… потушите 3–5 минут»
  и «Выложите пасту в сковороду к соусу… перемешайте на среднем огне»;
  сливочная паста с курицей — «томите соус на сковороде»;
  тофу — «готовьте на сковороде 2 минуты, помешивая»;
- en-шаги синхронизированы (heat → fry/simmer/toss с техникой);
- генератор (`scripts/gen/*`) синхронизирован с новым текстом, чтобы
  перегенерация не вернула «прогрейте»; метаданное `count` приведено
  к фактическому числу рецептов (554, прежде — устаревшие 541);
- `equipment.dart`: комментарий о духовочных приведён к факту базы —
  духовочных 102, больших ровно два (печенье, шарлотка), фильтр
  действительно срабатывает;
- тесты: guard «в базе нет „прогрейте“» расширен с завтраков на всю
  базу + новый guard «каждый шаг с „выпек“ называет сковороду».

## [0.6.4] — 2026-10-29

Техника на кухне: онбординг спрашивает, какая техника есть (духовка,
блендер, тостер), и планер подбирает блюда под неё. Блюда без нужной
техники не пропадают: если есть разумная замена — предлагаются с пометкой
«чем заменить» (духовка → плита, блендер → толкушка, тостер → сухая
сковорода); исключаются только большие духовочные блюда (4+ порций) —
их без духовки не приготовить. Схема БД — v10 (`user_profile.equipment`).
Заодно исправлены сбивающие формулировки «прогрейте» в кашах (репорт
владельца: каша только что сварена и горячая).

### Добавлено

- **Шаг онбординга «Какая техника есть на кухне?»**: всё выбрано по
  умолчанию — пользователь снимает галочки с отсутствующего; «Пропустить»
  = «всё есть». Донастройка — Профиль → «Техника на кухне».
- **Вывод требований по шагам рецепта** (`lib/ai/equipment.dart`, runtime,
  без перегенерации базы): «духовк*»/«запек*» → духовка, «блендер*»,
  «тостер*». Ловушки учтены: «выпекайте панкейки» — жарка на сковороде,
  техника из названий не выводится.
- **Правила замены**: замещаемое отсутствие — блюдо в плане с мягким
  штрафом скоринга (−12) и пометкой «замена: духовка → плита» в списке
  блюд и карточкой в деталях рецепта; духовка для блюда на 4+ порций —
  жёсткий фильтр с человеческой причиной в отчёте («нет техники:
  духовка — блюдо большое, замене не подлежит»).
- **Миграция БД v10**: `user_profile.equipment` (JSON-массив, nullable).
  null = «неизвестно/всё есть» — профили до v0.6.4 работают без
  изменений; явный пустой список = «техники нет».
- **Бэкап formatVersion 2**: экспорт пишет полные строки, поэтому колонка
  equipment попадает в копию автоматически; старое приложение чисто
  отклоняет новый файл (newerVersion), новое читает и старые копии.

### Исправлено

- Кашам (r0542, r0544–r0547) «Добавьте … и прогрейте N минут» заменено на
  «…перемешайте и поварите ещё N минут» — каша уже горячая, «прогреть»
  вводило в заблуждение. Супы/соусы не тронуты: там «прогреть» после
  соединения компонентов — корректный кулинарный термин.

## [0.6.3] — 2026-10-29

Экспорт/импорт данных — офлайн-замена облачного бэкапа: один JSON-файл,
который пользователь переносит сам (мессенджер, Диск, папка загрузок).
Схема БД — без изменений (v9); тестов 467 → 485. Запланированные ранее
«Историки цен» (Kroger/Open Prices в History) сняты с повестки —
вместо них по решению владельца сделан перенос данных.

### Добавлено

- **Экспорт резервной копии**: Настройки → «Данные» → «Экспорт данных».
  В конверт `formatVersion: 1` входят «сырые» строки SQLite: продукты
  (с ценой/валютой), профиль питания (диеты, нелюбимые, лечебные
  столы), сохранённые планы меню со списками покупок (снимки рецептов —
  планы самодостаточны), офлайн-кэш штрих-кодов, а также не-секретные
  настройки (тема, язык, напоминания, магазин источника цен). Файл
  `smart_fridge_backup_ГГГГММДД_ЧЧММ.json` уходит в системный шаринг
  (Share Plus) — пользователь сам выбирает место.
- **Импорт резервной копии**: Настройки → «Данные» → «Импорт данных».
  Выбор .json через системный пикер (SAF — без разрешений на
  хранилище); валидация конверта и обязательных колонок — ДО стирания
  текущих данных; замена — одна транзакция SQLite с учётом внешних
  ключей (planned_meals/shopping_items → meal_plans), идентификаторы
  строк сохраняются. После импорта: применение настроек, refresh
  холодильника/профиля/истории планов, перепланирование напоминаний.

### Безопасность

- **Секреты в бэкап не попадают (KEYS-1)**: Kroger client id/secret и
  ключ Wegmans остаются только в secure storage — в открытом JSON им
  не место; после импорта на новом устройстве вводятся заново.
  Белый список ключей настроек в `SettingsController` исключает перенос
  секретов даже при подделке файла.
- **Отказные сценарии до wipe**: чужой файл, массив вместо объекта,
  `formatVersion` из будущего, строки без обязательных колонок — импорт
  отклоняется с понятным сообщением, текущие данные не трогаются.

### Техническое

- Новые зависимости: `file_picker` 13.3.0 (выбор файла), `share_plus`
  13.3.1 (системный шаринг), `path_provider` (транзитивно) — размеры
  APK почти не меняются.
- `BackupService` (`lib/data/backup_service.dart`) — ядро без UI;
  `DataSection` (`lib/ui/settings/data_section.dart`) — секция
  настроек; 18 новых тестов (`test/data/backup_test.dart`,
  `test/state/settings_backup_test.dart`).

## [0.6.2] — 2026-10-28

Волна 3 внешнего аудита (38 P4) + главный запрос пользователей: русский
OCR (OCR-1 — закрыт по-настоящему, не ограничением). Схема БД — без
изменений (v9); тестов 425 → 460+.

### Добавлено

- **Русский OCR чеков (OCR-1)**: ML Kit Text Recognition v2 поддерживает
  только latin/chinese/devanagari/japanese/korean — кириллицы в списке
  нет (поддержка русского из Translation/Language ID на OCR не
  распространяется). Второй движок — **Tesseract** с моделью
  `tessdata_fast rus` (3,7 МБ, Apache-2.0, on-device): `AutoOcrEngine`
  сначала Tesseract (кириллица в тексте → результат берётся сразу),
  фолбэк — ML Kit latin для латиницы; качество сравнивается числом
  позиций, узнанных парсером чека. Вводится через экран чека без
  настроек; фактический рост APK: arm64 39,0 → 48,8 МБ, armv7
  31,1 → 38,8 МБ, x86_64 42,0 → 52,1 МБ (нативные библиотеки
  Tesseract + модель).
- **Валюта чека (SCAN-2)**: ₽/руб/р., $/usd, €/eur/евро, ₸/тенге, £/gbp
  распознаются в тексте чека (границы слов: «рубашка» не даёт RUB,
  «евросеть» — EUR); валюта попадает в продукты из чека.
- **Целые цены без копеек (SCAN-4)**: «МОЛОКО 89» распознаётся как цена
  89; 1 цифра и 4+ цифры (артикулы) не принимаются за цену.
- **Пагинация истории планов (DATA-5)**: `PlanDao.listPlans(offset:)` —
  планы старше 30 больше не «в базе, но недостижимы».
- **QR-коллектор (SHARE-4)**: приём страниц вынесен в `QrChunkCollector`
  — новая передача с тем же числом страниц больше не «залипает» на
  слотах сломанной (та же страница с другим содержимым начинает сбор
  заново), недобор сбрасывается по таймауту 45 с.
- **Счётчик тестов в CI (TEST-3)**: артефакт `test_count` — фактическое
  число тестов публикует CI, README не хранит неверифицируемое число.
- **Позитивные фиксации (LEG-7)**: схема «личный ключ пользователя»
  Kroger/Wegmans соответствует условиям их developer-программ; LEG-10:
  заметка о проверке товарного знака «Умный Холодильник» при
  коммерциализации (README).

### Исправлено

- **Планер**: джиттер детерминирован парой «блюдо × слот × зерно»
  (FNV-1a) — раньше зависел от порядка обхода кандидатов (AI-6);
  `LocalLlmPlanner` — живое звено цепи планировщика в main.dart, а не
  мёртвый каркас (AI-8); «не люблю соль» больше не исключает фасоль —
  сравнение по токенам, а не подстроке (AI-10); has_fish=false у 32
  ракообразных/моллюских рецептов (креветки/кальмары — не рыба;
  генератор исправлен синхронно) (REC-4); инвариант-тест «нет мёртвых
  ключей словаря» — 7 «неиспользуемых» ключей живут в категоризации
  штрих-кодов (REC-5).
- **Данные**: ленивое открытие БД под Future-замком — двойной open при
  старте больше не гонка (DATA-3); `ProfileDao.save` сам сохраняет
  created_at существующей строки (DATA-4).
- **Сеть/источники цен**: значения, попадающие в ПУТЬ URL (штрих-код
  OFF, SAP-код Пятёрочки, store/sku Wegmans), валидируются цифрами
  (NET-4); `throwNetwork` различает network и unexpected→unknown вместо
  мёртвой одинаковой ветки (NET-5); Wegmans `wasPrice/promoPrice` →
  oldPrice — скидки видны как «было/стало» (NET-8); Aldi «1.199,00 €»
  больше не 1.199 € — немецкий формат тысяч (NET-9).
- **Чеки**: «0 х Молоко» не даёт ноль позиций (SCAN-3).
- **QR/шаринг**: расхождение заголовка «n» с фактом = битая передача
  (SHARE-3); битая дата больше не «сегодня» — позиция отбрасывается и
  считается в `invalidCount` (SHARE-2); ручная навигация выключает
  автопрокрутку QR (UI-14).
- **UI/доступность**: «г» в покупках из ARB (UI-10); диапазон поля
  калоража = диапазону слайдера 1200–3500 (UI-11); контроллер диалога
  ручного ввода диспозится (UI-12); снятие последнего чипа дней пушей
  объясняет отказ, а не молчит (UI-13); TalkBack-действия «съел»/
  «удалить» на карточках холодильника (UI-15); ключ Wegmans маскируется
  (SEC-3).
- **Напоминания**: `granted ?? true` → `?? false` — null платформы не
  считается разрешением (NOTIF-5); даты в пушах локализуются —
  `initializeDateFormatting('ru')` на старте, ISO-запасной вид больше
  не постоянный (ST-3); `refresh()` с неизменными входами не делает
  полный resync пушей — отпечаток продуктов/настроек/локали/дня (ST-6).
- **Инфра**: gradle 4G/1G вместо 8G/4G, не влезавших в раннеры (PLAT-5);
  SECURITY.md перестал хардкодить версию; poll_gh_runs.py берёт токен
  из GH_TOKEN, а не из URL remote (INFRA-7); adaptive icon (PLAT-3) и
  UA OFF с kAppVersion (PLAT-4) закрыты в волнах 1–2 — отмечены.

### Техническое

- `flutter_tesseract_ocr` 0.4.31 (BSD-3) + tesseract4android (Apache-2.0)
  + tessdata_fast rus (Apache-2.0) — NOTICE дополнен, транзитивные
  лицензии перечислены (LEG-8).
- Схема БД не менялась (v9); публичный API парсера чека расширен
  (`parseReceiptDetailed`), `parseReceipt` сохранён.

### Добавлено

### Исправлено

- **Планировщик**: side-гарниры достижимы в обеде/ужине (AI-2); супы
  больше не выдавлены из обеда калоражем — штраф для супов/салатов

  ингредиенты + предупреждение (AI-4); список покупок честно считает
  накопленный дефицит по дням, без двойного вычета (AI-5); деривации

  яйца (AI-9).
- **Данные рецептов**: «Банан с шоколадом» больше не «веганский» с
  молоком (REC-2); снят gluten_free у 28 овсяных и 5 соево-соусных
  рецептов (REC-3); 2 майонезных салата сняты с vegan — все флаги
  согласованы с аллергенами (инвариант-тест).
- **Сеть**: таймаут обрывает подвисший запрос (закрытие клиента,
  NET-2) во всех семи сервисах; ключ Wegmans в заголовке
  Ocp-Apim-Subscription-Key вместо query-string (SEC-2, тест перевёрнут);
  сборка Mercadona не all-or-nothing — частичный кэш каждые 10 категорий,
  бюджет 60 с, отказ категории не аннулирует остальные (NET-7); секреты

- **Напоминания**: сериализация sync Future-замком (NOTIF-3); diff по

- **QR-приём**: валидация чужого payload — quantity/БЖУ/имя/штрих-код

  в базу (SHARE-1, враждебные тесты SHARE-5).
- **Чеки**: стоп-слова по границам слов — «Картофель», «Пакетик чая»,
  «Cashews», «Cardamom» больше не выбрасываются служебными стемами

## [0.5.1] — 2026-10-25

### Добавлено

- **Списание продуктов после «Приготовил»** (логика «съеденного»):
  в карточке рецепта появилась кнопка «Приготовил — вычесть из
  холодильника». Приложение само предлагает, что списать: ингредиенты
  матчатся по тем же ключам, что и в планере; первым списывается
  скоропортящееся (FIFO по сроку); весовые позиции — точными граммами
  (г/кг/мл/л, 1 мл ≈ 1 г), счётные — одной штукой по умолчанию.
  Каждый пункт с галочкой и (для штучных) степпером — автоматический
  режим по умолчанию, ручной контроль рядом: сняли галочку — позиция
  не тронется. Обнулившаяся позиция уходит в «съедено» (история
  сохраняется). «Готовить» ничего не списывает — еда ещё не потрачена;
  ручной свайп в холодильнике работает как раньше. Если один продукт
  закрывает несколько ингредиентов, списания показываются одной
  строкой, а остаток считает движок, а не вычитание из исходной
  массы. Кладовые (соль, специи) не списываются.
- **Выбор «что передать» в QR-обмене**: перед показом кода — список
  «Все несъеденные» (по умолчанию, как и было), «Скоропортящиеся
  (≤3 дней)» и «Выбрать вручную» — экран с чекбоксами, «выбрать все /
  снять все», счётчик и кнопка «Передать: N». Семье удобно передать
  всё, кроме уже съеденного, или только то, что вот-вот испортится.
- На экране QR теперь показывается число передаваемых продуктов.

### Изменено

- Тесты: 287 (+16: движок списания 13 — точные граммы, FIFO, штуки,

## [0.5.0] — 2026-10-25

### Добавлено

- **Учёт граммов в подборе рецептов**: раньше «50 г риса» закрывали
  «рис для плова», даже если риса явно мало. Теперь масса позиции в
  холодильнике (г/кг/мл/л; 1 мл ≈ 1 г) сравнивается с потребностью
  рецепта: ингредиент закрыт только если продукта хватает. Штуки и
  упаковки считаются достаточными — вес штуки без таблицы соответствий
  определить нельзя. Несколько позиций одного ключа суммируются, срок
  берётся самый близкий.
- **Список покупок с оценкой «докупить ≈N г»**: потребность по ключу
  суммируется по всем выбранным рецептам недели, из неё вычитается то,
  что есть в холодильнике. Для счётных позиций граммовая оценка не
  выдаётся (честно).
- **Несколько диет одновременно** (схема БД v4): профиль хранит список
  («халяль + веган», «кошер + без говядины» и т.п.), ограничения
  объединяются — рецепт обязан удовлетворять каждой выбранной диете.
  Выбор в онбординге и настройках переключён на мультичипы; старая
  единичная диета переносится в список при миграции.
- **Подсказки «почему рецепты не в меню»**: в плане появилась свёрнутая
  карточка с диагностикой жёстких фильтров — причина → количество
  исключённых рецептов + до трёх примеров («халяль: свинина — 20»,
  «кошер: мясо с молочным — 37», «аллергия: молоко», «готовка дольше
  N мин»). Отчёт сохраняется вместе с планом.
- **QR-обмен продуктами между телефонами** (идея друга проекта): без
  сервера, аккаунтов и интернета. Один телефон показывает серию
  QR-кодов со всеми активными продуктами (автопрокрутка), второй —
  сканирует непрерывно с прогрессом; дубликаты страниц и повторные
  коды безвредны, порядок не важен. Формат страниц — как в
  AmneziaVPN (qrCodeUtils.cpp): чанки по 850 байт, заголовок
  `int16be 1984 ‖ uint8 всего ‖ uint8 № ‖ uint32be длина`, base64url —
  до 255 страниц ≈ 216 КБ ≈ 3000 продуктов. Передаются название,
  категория, срок, количество, единица, штрих-код и КБЖУ; дубликаты
  штрих-кодов уже имеющихся продуктов пропускаются с честным итогом
  «добавлено N, пропущено дублей M». Диеты у каждого свои — передаются
  только продукты.

### Исправлено

- Граница чанка QR может проходить посреди многобайтового UTF-8
  символа: страницы хранятся байтами, декодирование — один раз на
  собранном payload (ловилось тестом «страницы в перемешанном порядке»).

### Изменено

- Схема БД v3 → v4 (только добавление колонок; данные не трогаются).
- RuleBasedPlanner: правила диет вынесены в dietExclusionReason /

- Тесты: 271 (+28: кодек QR 11, граммы 9, мульти-диеты 2, диагностика

  ввод. Форма продукта: категория подставляет типовой срок хранения,
  чипы «+2 дня / +7 дней», количество с единицами, штрих-код, заметка.
- **Сканер штрих-кодов** (`mobile_scanner` 7 / ML Kit, on-device):
  EAN-13, EAN-8, UPC-A/E, Code 128; фонарик, прицел; повторная покупка
  распознаётся по частично-уникальному индексу Шага 1 — «+1 шт» к
  количеству или правка карточки; ручной ввод кода как фолбэк при
  недоступной камере.
- **OCR чеков** (`image_picker` + `google_mlkit_text_recognition`,
  распознавание на устройстве): фото чека или кадр из галереи → парсер
  строк (цена на отдельной строке прикрепляется к позиции; количества
  «2 х» / «х2»; служебные строки магазинов/итогов/оплат отфильтрованы;
  дубликаты схлопываются с суммированием) → подтверждение с правкой
  названий и снятием лишних → массовое добавление; категория угадывается
  по ключевым словам RU.
- **Локальные пуш-напоминания о просрочке** (по ТЗ «за 1–2 дня»):
  `flutter_local_notifications` + `timezone`; за 2 и/или 1 день
  (настраивается) в выбранный час суток; детерминированные идентификаторы
  `(productId*10 + daysBefore)`, поэтому правка/удаление продукта и смена
  настроек мгновенно отменяют лишние пуши (сверка desired ↔ pending);
  канал `expiry_warnings`; восстановление расписания после перезагрузки
  (boot-приёмники); фолбэк exact→inexact будильники и UTC при
  недоступной таймзоне; синхронизация — при старте, после каждой мутации
  холодильника и при смене настроек.
- **Онбординг профиля** (по ТЗ «настраивает один раз»): 4 шага —
  приветствие → суточный калораж и приёмы пищи → диета и аллергены →
  напоминания (с запросом прав Android 13+/iOS). «Пропустить» сохраняет
  дефолтный профиль.
- **Экран настроек**: профиль питания (слайдер калоража, БЖУ с
  авторасчётом 30/30/40, 6 диет, 9 аллергенов, 2–6 приёмов пищи, регион
  для сезонности) + блок напоминаний (вкл/выкл, дни, время).
- **Экран «Мое меню»**: пустое состояние с кнопкой Суперпланера;
  недельная сетка — карточки дней с суммами БЖУ и чипами «съесть раньше»
  (продукты с истекающим сроком); детали рецепта (КБЖУ на порцию,
  ингредиенты с граммовками, пошаговое приготовление); сохранить /
  «другой вариант» (новый seed) / история с открытием и удалением планов.
- **Экран «Список покупок»**: чекбоксы недостающих ингредиентов плана,
  прогресс «куплено N из M», кнопка «убрать купленные»
  (`PlanDao.deleteCheckedShopping`).
- Локализация: ~120 новых строк RU/EN (экраны, сканер, чек, покупки,
  онбординг, напоминания, категории, диеты, аллергены, слоты).

## [0.2.0] — 2026-10-24

### Добавлено (Шаг 2: AI-слой — «Суперпланер»)

- **Встроенная база рецептов** `assets/data/recipes.json`: 541 блюдо
  (RU + EN), 108 завтраков, 34 супа, 331 основное блюдо, 34 салата,
  гарниры, перекусы, десерты. КБЖУ на порцию, аллергены, флаги диет
  (vegetarian/vegan/gluten_free/low_carb), время готовки, шаги
  приготовления. База собирается скриптом `scripts/gen_recipes.py`
  (комбинаторика проверенных шаблонов + таблица пищевой ценности),
  валидируется тестами.
- **RuleBasedPlanner** — детерминированный движок генерации меню,
  работает офлайн «из коробки», без сети и без модели:
  - жёсткие фильтры безопасности: аллергии и диета исключают рецепты
    целиком, независимо от любого скоринга;
  - приоритет сроков: продукты с истекающим сроком (≤ 2 дней) получают
    наибольший бонус и попадают в первые дни плана, приём помечается
    «срочно: …»;
  - попадание в целевую калорийность слота (распределение по
    mealsPerDay: 2–6 приёмов, доли завтрак/обед/ужин/перекусы);
  - разнообразие: анти-повторы того же рецепта, «семьи» блюда
    (главный ингредиент) и гарнира;
  - список покупок (недостающие ингредиенты, без кладовых) и
    предупреждения (срочные продукты вне плана, отклонения калоража);
  - детерминизм: seed → воспроизводимый план, новый seed → новая неделя.
- **IngredientMatcher** — сопоставление продуктов холодильника с
  ингредиентами рецептов: нормализация (регистр/ё/пунктуация) +
  словарь из ~140 синонимов RU и EN («куриное филе» → chicken_breast);
  непознанные продукты не роняют генерацию, а попадают в предупреждения.
- **Архитектура провайдеров AI** (интерфейс `MealPlanner`):
  RuleBasedPlanner — по умолчанию и фолбэк; `LocalLlmPlanner` — каркас
  локальной LLM (Gemma/MediaPipe, подключение на Шаге 3) с прозрачным
  фолбэком на движок рецептов; интерфейс-заготовка `PlatformAiPlanner`
  под Android AICore / Apple Foundation Models. Качество и безопасность
  гарантированы слоем фильтров, а не моделью.
- **Схема БД v2 + миграция 1→2**: таблицы `meal_plans`, `planned_meals`
  (рецепты хранятся полными JSON-снимками — планы самодостаточны),
  `shopping_items` (чекбоксы покупок). Данные Шага 1 при миграции
  сохраняются — закреплено тестом.
- **PlanDao** и **PlanController**: генерация → сохранение → история →
  открытие → удаление, отметки «куплено»; контроллер уже подключён
  в `main.dart` (экран планера — Шаг 3).
- 129 тестов (было 24): матчер, калораж, целостность всей базы рецептов,
  интеграционные сценарии планера (аллергии/диеты/сроки/детерминизм),
  DAO планов, миграция схемы, PlanController.

### Приватность

- Вся генерация меню — локально; сеть по-прежнему не используется.
