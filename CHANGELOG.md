# Changelog

Формат — в духе [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/);
версии — по [SemVer](https://semver.org/lang/ru/). Разработка идёт поэтапно

## [0.6.0] — 2026-10-28

Волна 1 внешнего аудита (2026-10-28, 91 находка: 13 P2 — исправлены,
включая смежные P3/P4 по касанию).

### Исправлено

- **Откат версии больше не сносит базу (DATA-1, P2)**: `openDatabase`
  получил `onDowngrade` — при запуске старого APK схема остаётся новой
  (миграции строго аддитивны), данные целы; раньше sqflite молча удалял
  файл базы.
- **Точные будильники без смещения на часовой пояс (NOTIF-1, P2)**:
  UTC-фолбэк планировщика не вычитает `timeZoneOffset` из уже-локального
  времени — раньше будильники приходили на |offset| часов раньше/позже
  (10:00 МСК → 07:00). Конверсия вынесена в чистую функцию с тестом.
- **Вечный спиннер цены (NET-6, P2)**: TypeError от кривого JSON
  неофициальных API больше не уводит запрос в unhandled zone — кнопка
  цены снимает загрузку и показывает «цена не подставилась». Парсеры
  всех шести источников читают JSON через безопасные `jsonStr`/`jsonNum`
  вместо `as`-кастов.
- **Утечка http.Client ×7 (NET-1, P2)**: каждый ценовой сервис живёт на
  одном переиспользуемом клиенте (пик утечки — 153 клиента за проход
  индекса Mercadona).
- **Debug-краш «Приготовил» (UI-2, P2)**: `Localizations.localeOf`
  перенесён из `initState` в `didChangeDependencies` — зависимый lookup
  до завершения initState давал FlutterError в debug-сборках.
- **USE_EXACT_ALARM убран (ALARM-1, P2)**: политика Play резервирует
  разрешение для приложений-будильников; достаточно
  `SCHEDULE_EXACT_ALARM` с рантайм-фолбэком exact → inexact (уже был).
- **Аллерген по умолчанию (AI-7, P3)**: повреждённый ключ аллергена в
  профиле отбрасывается, а не превращается в аллергию на молоко
  (внезапная потеря ~210 рецептов без объяснения).

### Изменено

- **Столы Певзнера 4/12/13/14 — щадящая калибровка (AI-1, P2)**: запреты
  выверены по классике столов (свёкла отварная в №4, подсушенный хлеб и
  умеренный перец в №13, нейтральное масло и кислые фрукты в №14, только
  сильные возбудители в №12) — вырожденные пулы слотов (3/0/4/1 блюда)
  устранены; пулы по (стол × слот) закреплены матрицей в тестах.
- **Предупреждения о вырожденных слотах**: планер пишет в warnings
  «в слоте … осталось N рецептов — меню будет повторяться», когда после
  жёстких фильтров пул слота меньше семи блюд (недельная норма).
- **База завтраков расширена (REC-1, P2)**: +13 рецептов (541 → 554) —
  безмолочные/безъяичные/веганские каши на воде, тофу-скрэмбл, смузи и
  печёные фрукты; при молоко+яйца теперь ≥ 5 завтраков вместо одного
  (инвариант-тест закреплён).
- **«Большая 14» ЕС — теперь честно 14 (LEG-2, P2)**: чип «моллюски»
  разделён на «ракообразные» и «моллюски» (24 → 25 аллергенов); старые
  профили с чипом `shellfish` мигрируют на оба новых консервативно;
  деривация `shrimp`/`squid` из ключей ингредиентов работает на runtime.
- **OCR чеков — честная маркировка (OCR-1, P2)**: ML Kit не поддерживает
  кириллицу — экран чека и README прямо говорят «латиница, кириллические
  позиции вводите вручную».
- **Индекс цен Mercadona переехал в SQLite (SCAN-6, P2)**: схема БД v8,
  таблица `mercadona_index`; SharedPreferences больше не раздувается на
  ≈0,5 МБ XML (jank старта); старый prefs-индекс импортируется один раз
  и удаляется.
- **Версии синхронно (VER-1, P3)**: `kAppVersion` 0.6.0 = pubspec; UA
  Open Food Facts собирается из константы, а не вечного «0.4».
- **Права без противоречия GitHub ToS (LEG-1, P2)**: README «Права»
  переформулирован (исходники открыты для изучения; форки/PR — по ToS
  GitHub; APK — freeware; история Apache-окна зафиксирована) — запрет
  «use/copy/distribute», неисполнимый для публичного репо, убран.
- **NOTICE дополнен (NOTICE-1, P3)**: Wegmans, Mercadona, Aldi Süd
  раскрыты наравне с остальными источниками; SECURITY.md — 0.6.0.

### Техническое

- Миграция v6 → v8 покрыта тестом (TEST-1): данные v0.5.8 переживают

## [0.5.9] — 2026-10-26

### Добавлено

- **Лечебные диеты — столы по Певзнеру №1–15**: классическая система
  нумерованных диетических столов добавлена в профиль питания отдельной
  секцией (после аллергий). Каждый стол — номер, название, для каких
  состояний назначается и что исключает; кнопка «что означают столы»
  открывает полный справочник прямо на экране профиля.
- **Жёсткий фильтр планера**: выбранные столы работают наравне с
  аллергиями (безопасность, не скоринг) — рецепты с запрещёнными
  продуктами исключаются целиком, а отчёт «почему исключено» получает
  причину вида «стол №5: шампиньоны». Ограничения комбинируются:
  рецепт обязан соответствовать каждому выбранному столу; столы 11
  (усиленное питание) и 15 (общий) в базе рецептов запретов не имеют.
- **Механика — по составу, без перегенерации базы**: запреты заданы
  ключами ингредиентов канонического словаря и проверяются по составу
  рецептов при генерации (паттерн аллергенов v0.5.4/v0.5.7). Списки
  калиброваны по реальной базе (scripts/pevzner_coverage.py): у каждого
  стола с запретами остаётся от 81 до 457 рецептов — недельному планеру
  хватает; принцип консервативный (лучше исключить лишнее). Стол 4
  реализован в щадящем варианте 4Б (свежие овощи-салаты исключены,
  пассерованные лук и перец в горячих блюдах — допустимы).
- **Схема БД v7**: колонка `user_profile.medical_diets` (JSON-массив
  ключей table1…table15), накат с любой предыдущей версии; неизвестные
  ключи из старых версий безопасно отбрасываются при чтении.

### Примечания

- Стол назначает врач: в интерфейсе выбора есть предупреждение, что
  описания справочные и не заменяют индивидуальные указания.
- +19 тестов: каталог (полнота №1–15, ключи запретов существуют в базе,
  размер пула каждого стола закреплён ожиданиями), поиск нарушений,
  фильтр планера (включая построение недельного плана на столе 4),
  round-trip профиля и отбрасывание мусорных ключей. Всего 386.

## [0.5.8] — 2026-10-26

### Добавлено

- **Источники цен — Mercadona / Aldi Süd / Wegmans (эксперимент)**:
  список стран расширен с 3 до 6; все новые источники встроены в общий
  контракт v0.5.6 (`PriceHit`, `pickBestPriceHit`, честные фолбэки) —
  в настройках выбирается один, форма продукта и карточка работают
  с ним одинаково.
  * **Mercadona (Испания)** — открытый каталог tienda.mercadona.es без
    ключей. Поискового эндпоинта у каталога нет, поэтому индекс товаров
    (26 верхних → 152 категории 1-го уровня) собирается один раз прямо
    с устройства (~20–40 с), кэшируется в памяти и SharedPreferences
    и дальше отвечает мгновенно; раз в 3 дня обновляется в фоне.
    Цены складские (без выбора магазина), поиск по названию.
  * **Aldi Süd (Германия)** — публичный поиск api.aldi-sued.de
    (`/v3/product-search`): цены полки всей сети, без выбора магазина,
    без ключей. Akamai блокирует VPN и датацентровые IP — при блоке
    цена просто не подставляется (паттерн Пятёрочки). Кастомный
    User-Agent не отправляется: API отклоняет переопределённый UA.
  * **Wegmans (США)** — официальный открытый API
    (developer.wegmans.io): пользователь сам бесплатно получает
    subscription-key и вставляет его в настройках (хранится только на
    устройстве), выбирает магазин из списка (~110 магазинов на
    северо-востоке США), цены — конкретного магазина. Поиск двухшаговый:
    /products/search → цены первых 4 sku.
- Исправлено расхождение версии в «О приложении» (constants.dart
  отставал от pubspec с v0.5.7).

### Техническое

- `lib/scan/mercadona_lookup.dart`: парсер категории (рекурсивный обход
  `categories`/`products`, `price_instructions.unit_price` — цена за
  упаковку, `previous_unit_price` — до скидки), компактное
  кодирование индекса (~7 000 товаров в SharedPreferences), сборка
  с паузой 100 мс между категориями, single-flight гарантия одной
  сборки, TTL 3 дня с фоновым обновлением (поиск отвечает по старому
  индексу, не дожидаясь сети).
- `lib/scan/aldi_lookup.dart`: парсер JSON-API (цены целыми евроцентами:
  `amountRelevant` приоритетнее `amount`; `wasPriceDisplay` «2,49 €» —
  немецкий формат в oldPrice; `notForSale` ≠ «нет на полке»,
  `discontinued` — пропуск), допустимые лимиты страницы {12,16,24,30,
  32,48,60}, конверт ошибок `{"errors":[]}` с HTTP 200 трактуется как
  «недоступен», а не «пусто».
- `lib/scan/wegmans_lookup.dart`: api-version=2018-10-18 и
  subscription-key query-параметром (официальная коллекция Wegmans.io);
  парсеры stores/search/prices устойчивы к разнобою схем
  (store/storeNumber, адрес объектом или строкой); цена отдельного sku,
  не полученная, не валидит весь поиск (кроме 401/403 → auth).
- Схема БД не менялась: значения `price_source` расширены
  (`mercadona` / `aldi` / `wegmans`). +28 тестов (всего 366): парсеры
  на фикстурах (Mercadona — реальный ответ каталога, Aldi — схема
  из открытых исходников aldiscount, Wegmans — по официальной
  документации), сборка индекса и персист, URL/заголовки/параметры
  (включая отсутствие User-Agent у Aldi), auth/blocked/network.

## [0.5.5] — 2026-10-26

### Добавлено

- **Цены Пятёрочки (эксперимент)** — второй источник данных после Open
  Food Facts. Включается в настройках: переключатель + SAP-код магазина
  (4 символа, например `35XY`). При добавлении продукта цена подставляется
  автоматически: поиск по названию прямо с устройства (запрос к каталогу
  5ka.ru идёт с IP пользователя — WAF Пятёрочки пускает только «домашние»
  IP, серверные мосты невозможны в принципе). Под формой показывается,
  какой товар совпал; цена также видна в карточке холодильника. Ручной
  ввод цены доступен всегда, фича выключена по умолчанию.
- Честный фолбэк: при блокировке (включён VPN — Пятёрочка блокирует и
  VPN-IP), отсутствии сети или пустой выдаче цена просто не подставляется,
  всё остальное работает как раньше. Источник цены сохраняется в базу
  (`pyaterochka` / `manual`) вместе с моментом обновления.

### Техническое

- Миграция БД v5 → v6: колонки `products.price`, `price_updated_at`,
  `price_source` (только добавление, данные не трогаются).
- Новый сервис `PyaterochkaService` (`lib/scan/pyaterochka_lookup.dart`):

## [0.5.1] — 2026-10-25

### Добавлено

- **Списание продуктов после «Приготовил»** (логика «съеденного»):
  в карточке рецепта появилась кнопка «Приготовил — вычесть из
  холодильника». Приложение само предлагает, что списать: ингредиенты
  матчатся по тем же ключам, что и в планере; первым списывается
  скоропортящееся (FIFO по сроку); весовые позиции — точными граммами
  (г/кг/мл/л, 1 мл ≈ 1 г), счётные — одной штукой по умолчанию.
  Каждый пункт с галочкой и (для штучных) степпером — автоматический
  режим по умолчанию, ручной контроль рядом: сняли галочку — позиция
  не тронется. Обнулившаяся позиция уходит в «съедено» (история
  сохраняется). «Готовить» ничего не списывает — еда ещё не потрачена;
  ручной свайп в холодильнике работает как раньше. Если один продукт
  закрывает несколько ингредиентов, списания показываются одной
  строкой, а остаток считает движок, а не вычитание из исходной
  массы. Кладовые (соль, специи) не списываются.
- **Выбор «что передать» в QR-обмене**: перед показом кода — список
  «Все несъеденные» (по умолчанию, как и было), «Скоропортящиеся
  (≤3 дней)» и «Выбрать вручную» — экран с чекбоксами, «выбрать все /
  снять все», счётчик и кнопка «Передать: N». Семье удобно передать
  всё, кроме уже съеденного, или только то, что вот-вот испортится.
- На экране QR теперь показывается число передаваемых продуктов.

## [0.5.0] — 2026-10-25

### Добавлено

- **Учёт граммов в подборе рецептов**: раньше «50 г риса» закрывали
  «рис для плова», даже если риса явно мало. Теперь масса позиции в
  холодильнике (г/кг/мл/л; 1 мл ≈ 1 г) сравнивается с потребностью
  рецепта: ингредиент закрыт только если продукта хватает. Штуки и
  упаковки считаются достаточными — вес штуки без таблицы соответствий
  определить нельзя. Несколько позиций одного ключа суммируются, срок
  берётся самый близкий.
- **Список покупок с оценкой «докупить ≈N г»**: потребность по ключу
  суммируется по всем выбранным рецептам недели, из неё вычитается то,
  что есть в холодильнике. Для счётных позиций граммовая оценка не
  выдаётся (честно).
- **Несколько диет одновременно** (схема БД v4): профиль хранит список
  («халяль + веган», «кошер + без говядины» и т.п.), ограничения
  объединяются — рецепт обязан удовлетворять каждой выбранной диете.
  Выбор в онбординге и настройках переключён на мультичипы; старая
  единичная диета переносится в список при миграции.
- **Подсказки «почему рецепты не в меню»**: в плане появилась свёрнутая
  карточка с диагностикой жёстких фильтров — причина → количество
  исключённых рецептов + до трёх примеров («халяль: свинина — 20»,
  «кошер: мясо с молочным — 37», «аллергия: молоко», «готовка дольше
  N мин»). Отчёт сохраняется вместе с планом.
- **QR-обмен продуктами между телефонами** (идея друга проекта): без
  сервера, аккаунтов и интернета. Один телефон показывает серию
  QR-кодов со всеми активными продуктами (автопрокрутка), второй —
  сканирует непрерывно с прогрессом; дубликаты страниц и повторные
  коды безвредны, порядок не важен. Формат страниц — как в
  AmneziaVPN (qrCodeUtils.cpp): чанки по 850 байт, заголовок
  `int16be 1984 ‖ uint8 всего ‖ uint8 № ‖ uint32be длина`, base64url —
  до 255 страниц ≈ 216 КБ ≈ 3000 продуктов. Передаются название,
  категория, срок, количество, единица, штрих-код и КБЖУ; дубликаты
  штрих-кодов уже имеющихся продуктов пропускаются с честным итогом
  «добавлено N, пропущено дублей M». Диеты у каждого свои — передаются
  только продукты.

### Исправлено

- Граница чанка QR может проходить посреди многобайтового UTF-8
  символа: страницы хранятся байтами, декодирование — один раз на
  собранном payload (ловилось тестом «страницы в перемешанном порядке»).

- Схема БД v3 → v4 (только добавление колонок; данные не трогаются).
- RuleBasedPlanner: правила диет вынесены в dietExclusionReason /

  «2 х» / «х2»; служебные строки магазинов/итогов/оплат отфильтрованы;
  дубликаты схлопываются с суммированием) → подтверждение с правкой
  названий и снятием лишних → массовое добавление; категория угадывается
  по ключевым словам RU.
- **Локальные пуш-напоминания о просрочке** (по ТЗ «за 1–2 дня»):
  `flutter_local_notifications` + `timezone`; за 2 и/или 1 день
  (настраивается) в выбранный час суток; детерминированные идентификаторы
  `(productId*10 + daysBefore)`, поэтому правка/удаление продукта и смена
  настроек мгновенно отменяют лишние пуши (сверка desired ↔ pending);
  канал `expiry_warnings`; восстановление расписания после перезагрузки
  (boot-приёмники); фолбэк exact→inexact будильники и UTC при
  недоступной таймзоне; синхронизация — при старте, после каждой мутации
  холодильника и при смене настроек.
- **Онбординг профиля** (по ТЗ «настраивает один раз»): 4 шага —
  приветствие → суточный калораж и приёмы пищи → диета и аллергены →
  напоминания (с запросом прав Android 13+/iOS). «Пропустить» сохраняет
  дефолтный профиль.
- **Экран настроек**: профиль питания (слайдер калоража, БЖУ с
  авторасчётом 30/30/40, 6 диет, 9 аллергенов, 2–6 приёмов пищи, регион
  для сезонности) + блок напоминаний (вкл/выкл, дни, время).
- **Экран «Мое меню»**: пустое состояние с кнопкой Суперпланера;
  недельная сетка — карточки дней с суммами БЖУ и чипами «съесть раньше»
  (продукты с истекающим сроком); детали рецепта (КБЖУ на порцию,
  ингредиенты с граммовками, пошаговое приготовление); сохранить /
  «другой вариант» (новый seed) / история с открытием и удалением планов.
- **Экран «Список покупок»**: чекбоксы недостающих ингредиентов плана,
  прогресс «куплено N из M», кнопка «убрать купленные»
  (`PlanDao.deleteCheckedShopping`).
- Локализация: ~120 новых строк RU/EN (экраны, сканер, чек, покупки,
  онбординг, напоминания, категории, диеты, аллергены, слоты).

## [0.2.0] — 2026-10-24

### Добавлено (Шаг 2: AI-слой — «Суперпланер»)

- **Встроенная база рецептов** `assets/data/recipes.json`: 541 блюдо
  (RU + EN), 108 завтраков, 34 супа, 331 основное блюдо, 34 салата,
  гарниры, перекусы, десерты. КБЖУ на порцию, аллергены, флаги диет
  (vegetarian/vegan/gluten_free/low_carb), время готовки, шаги
  приготовления. База собирается скриптом `scripts/gen_recipes.py`
  (комбинаторика проверенных шаблонов + таблица пищевой ценности),
  валидируется тестами.
- **RuleBasedPlanner** — детерминированный движок генерации меню,
  работает офлайн «из коробки», без сети и без модели:
  - жёсткие фильтры безопасности: аллергии и диета исключают рецепты
    целиком, независимо от любого скоринга;
  - приоритет сроков: продукты с истекающим сроком (≤ 2 дней) получают
    наибольший бонус и попадают в первые дни плана, приём помечается
    «срочно: …»;
  - попадание в целевую калорийность слота (распределение по
    mealsPerDay: 2–6 приёмов, доли завтрак/обед/ужин/перекусы);
  - разнообразие: анти-повторы того же рецепта, «семьи» блюда
    (главный ингредиент) и гарнира;
  - список покупок (недостающие ингредиенты, без кладовых) и
    предупреждения (срочные продукты вне плана, отклонения калоража);
  - детерминизм: seed → воспроизводимый план, новый seed → новая неделя.
- **IngredientMatcher** — сопоставление продуктов холодильника с
  ингредиентами рецептов: нормализация (регистр/ё/пунктуация) +
  словарь из ~140 синонимов RU и EN («куриное филе» → chicken_breast);
  непознанные продукты не роняют генерацию, а попадают в предупреждения.
- **Архитектура провайдеров AI** (интерфейс `MealPlanner`):
  RuleBasedPlanner — по умолчанию и фолбэк; `LocalLlmPlanner` — каркас
  локальной LLM (Gemma/MediaPipe, подключение на Шаге 3) с прозрачным
  фолбэком на движок рецептов; интерфейс-заготовка `PlatformAiPlanner`
  под Android AICore / Apple Foundation Models. Качество и безопасность
  гарантированы слоем фильтров, а не моделью.
- **Схема БД v2 + миграция 1→2**: таблицы `meal_plans`, `planned_meals`
  (рецепты хранятся полными JSON-снимками — планы самодостаточны),
  `shopping_items` (чекбоксы покупок). Данные Шага 1 при миграции
  сохраняются — закреплено тестом.
- **PlanDao** и **PlanController**: генерация → сохранение → история →
  открытие → удаление, отметки «куплено»; контроллер уже подключён
  в `main.dart` (экран планера — Шаг 3).
- 129 тестов (было 24): матчер, калораж, целостность всей базы рецептов,
  интеграционные сценарии планера (аллергии/диеты/сроки/детерминизм),
  DAO планов, миграция схемы, PlanController.

### Приватность

- Вся генерация меню — локально; сеть по-прежнему не используется.
