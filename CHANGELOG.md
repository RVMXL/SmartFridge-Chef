# Changelog

Формат — в духе [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/);
версии — по [SemVer](https://semver.org/lang/ru/). Разработка идёт поэтапно
по ТЗ: каждый шаг = отдельная версия и отдельная миграция схемы БД.

## [0.4.0] — 2026-10-24

### Добавлено (Шаг 3.1: автопоиск по штрих-коду)

- **Автопоиск товара по штрих-коду**: незнакомый код сначала проверяется
  в локальном кэше, затем в открытой базе Open Food Facts (без ключей,
  аккаунтов и отправки данных с устройства — только GET самого кода).
  Нашлось — название (с брендом, если он «потребительский») и категория
  подставляются в форму сами, а категория задаёт типовой срок хранения;
  не нашлось или сети нет — прежний ручной ввод с пояснением.
- **Локальный кэш штрих-кодов (схема БД v3)**: новая таблица
  `barcode_cache` — найденный однажды товар распознаётся офлайн
  навсегда; отрицательные результаты не кэшируются (открытая база
  постоянно пополняется).
- Маппинг ~60 тегов категорий OFF на категории приложения (молочное,
  мясо, рыба, овощи, фрукты, хлеб, крупы, заморозка, напитки, сладкое,
  соусы); корпоративные названия брендов («COCA-COLA SERVICES SA/NV»,
  «ООО …») в карточку не попадают.

### Изменено

- Разрешение `INTERNET` добавлено в манифест — единственный сетевой
  запрос приложения; формулировки README (офлайн-first, приватность)
  уточнены соответственно. Схема БД v2 → v3, миграция только добавляет
  таблицу; тестов теперь 190 (+21).

## [0.3.1] — 2026-10-24

### Изменено

- **Имя приложения локализовано**: «Умный Холодильник» при русском языке
  системы, Smart Fridge в остальных (Android: `@string/app_name` с

- **Лицензия заменена**: Apache-2.0 убран (файл `LICENSE` удалён), код —
  только для просмотра (раздел «Права» в README, NOTICE); приложение
  предоставляется без гарантий, автор не несёт ответственности за
  проблемы при использовании.
- **Все релизы публикуются как пре-релизы** (флаг `--prerelease` в
  workflow; действующий релиз v0.3.0 помечен задним числом).

## [0.3.0] — 2026-10-24

### Добавлено (Шаг 3: экраны, сканер + OCR, локальные пуши)

- **Экран «Мой холодильник»** (по ТЗ): карточки продуктов с цветной полосой
  свежести (зелёный / жёлтый ≤ 2 дней / красный) и легендой; поиск по
  названию; сортировка по сроку / имени / категории; свайп вправо «съел»,
  влево — выбор «выбросить / удалить»; тап — редактирование; pull-to-refresh.
- **Быстрый ввод тремя путями**: скан штрих-кода, фото чека (OCR), ручной
  ввод. Форма продукта: категория подставляет типовой срок хранения,
  чипы «+2 дня / +7 дней», количество с единицами, штрих-код, заметка.
- **Сканер штрих-кодов** (`mobile_scanner` 7 / ML Kit, on-device):
  EAN-13, EAN-8, UPC-A/E, Code 128; фонарик, прицел; повторная покупка
  распознаётся по частично-уникальному индексу Шага 1 — «+1 шт» к
  количеству или правка карточки; ручной ввод кода как фолбэк при
  недоступной камере.
- **OCR чеков** (`image_picker` + `google_mlkit_text_recognition`,
  распознавание на устройстве): фото чека или кадр из галереи → парсер
  строк (цена на отдельной строке прикрепляется к позиции; количества
  «2 х» / «х2»; служебные строки магазинов/итогов/оплат отфильтрованы;
  дубликаты схлопываются с суммированием) → подтверждение с правкой
  названий и снятием лишних → массовое добавление; категория угадывается
  по ключевым словам RU.
- **Локальные пуш-напоминания о просрочке** (по ТЗ «за 1–2 дня»):
  `flutter_local_notifications` + `timezone`; за 2 и/или 1 день
  (настраивается) в выбранный час суток; детерминированные идентификаторы
  `(productId*10 + daysBefore)`, поэтому правка/удаление продукта и смена
  настроек мгновенно отменяют лишние пуши (сверка desired ↔ pending);
  канал `expiry_warnings`; восстановление расписания после перезагрузки
  (boot-приёмники); фолбэк exact→inexact будильники и UTC при
  недоступной таймзоне; синхронизация — при старте, после каждой мутации
  холодильника и при смене настроек.
- **Онбординг профиля** (по ТЗ «настраивает один раз»): 4 шага —
  приветствие → суточный калораж и приёмы пищи → диета и аллергены →
  напоминания (с запросом прав Android 13+/iOS). «Пропустить» сохраняет
  дефолтный профиль.
- **Экран настроек**: профиль питания (слайдер калоража, БЖУ с
  авторасчётом 30/30/40, 6 диет, 9 аллергенов, 2–6 приёмов пищи, регион
  для сезонности) + блок напоминаний (вкл/выкл, дни, время).
- **Экран «Мое меню»**: пустое состояние с кнопкой Суперпланера;
  недельная сетка — карточки дней с суммами БЖУ и чипами «съесть раньше»
  (продукты с истекающим сроком); детали рецепта (КБЖУ на порцию,
  ингредиенты с граммовками, пошаговое приготовление); сохранить /
  «другой вариант» (новый seed) / история с открытием и удалением планов.
- **Экран «Список покупок»**: чекбоксы недостающих ингредиентов плана,
  прогресс «куплено N из M», кнопка «убрать купленные»
  (`PlanDao.deleteCheckedShopping`).
- Локализация: ~120 новых строк RU/EN (экраны, сканер, чек, покупки,
  онбординг, напоминания, категории, диеты, аллергены, слоты).

### Изменено

- `UserProfile.copyWith` — добавлен параметр `createdAt` (сохранение даты
  создания профиля при обновлениях).
- `SettingsController` — настройки напоминаний: включённость, набор дней
  {1, 2} (CSV), час 0–23 (дефолты: вкл, [2, 1], 9:00).
- iOS: deployment target 15.5 (требование ML Kit), Podfile, описания
  прав камеры/галереи в Info.plist.
- Android: права `CAMERA`, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`,
  `SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM`; приёмники
  flutter_local_notifications; `uses-feature camera` необязателен.

### Приватность

- Сеть по-прежнему не используется вовсе: штрих-коды и чеки
  распознаются локально (ML Kit), база продуктов наполняется из
  истории пользователя и ручного ввода; изображение чека никуда не
  отправляется.
- 169 тестов (было 129): план напоминаний (границы «час будильника
  прошёл», кап 100, статусы), стабильность и int32 id, парсер чеков
  (RU/EN, цены отдельной строкой, количества, дубликаты),
  ProductController (CRUD, дубликаты штрих-кодов, поиск, сортировка,
  синхронизация пушей с фейковым планировщиком), настройки напоминаний,
  список покупок.

### Инфраструктура релизов

- `.gitignore` усилен: ключи подписи Android (`*.jks`, `*.keystore`,
  `.p12`, `key.properties`, `.gradle/`, `local.properties`) и служебные
  файлы Flutter/iOS гарантированно не попадают в репозиторий.
- Release-подпись в `android/app/build.gradle.kts`: приоритет —
  переменные окружения (GitHub Secrets), затем локальный
  `android/key.properties`; без ключа — откат на debug-подпись, чтобы
  `flutter run --release` работал у всех.
- Новый workflow `release.yml`: пуш тега `v*` → gen-l10n + analyze +
  тесты → восстановление ключа из секретов → подписанный APK →
  автоматический GitHub Release. Секреты: `KEYSTORE_BASE64`,
  `KEYSTORE_PASSWORD`, `KEYSTORE_KEY_ALIAS`, `KEYSTORE_KEY_PASSWORD`.
- Android-сборка: включён core library desugaring (требование
  `flutter_local_notifications`) — `coreLibraryDesugaringEnabled`,
  `multiDexEnabled` и зависимость `desugar_jdk_libs:2.1.4`; поймано
  первой CI-сборкой релиза.

## [0.2.0] — 2026-10-24

### Добавлено (Шаг 2: AI-слой — «Суперпланер»)

- **Встроенная база рецептов** `assets/data/recipes.json`: 541 блюдо
  (RU + EN), 108 завтраков, 34 супа, 331 основное блюдо, 34 салата,
  гарниры, перекусы, десерты. КБЖУ на порцию, аллергены, флаги диет
  (vegetarian/vegan/gluten_free/low_carb), время готовки, шаги
  приготовления. База собирается скриптом `scripts/gen_recipes.py`
  (комбинаторика проверенных шаблонов + таблица пищевой ценности),
  валидируется тестами.
- **RuleBasedPlanner** — детерминированный движок генерации меню,
  работает офлайн «из коробки», без сети и без модели:
  - жёсткие фильтры безопасности: аллергии и диета исключают рецепты
    целиком, независимо от любого скоринга;
  - приоритет сроков: продукты с истекающим сроком (≤ 2 дней) получают
    наибольший бонус и попадают в первые дни плана, приём помечается
    «срочно: …»;
  - попадание в целевую калорийность слота (распределение по
    mealsPerDay: 2–6 приёмов, доли завтрак/обед/ужин/перекусы);
  - разнообразие: анти-повторы того же рецепта, «семьи» блюда
    (главный ингредиент) и гарнира;
  - список покупок (недостающие ингредиенты, без кладовых) и
    предупреждения (срочные продукты вне плана, отклонения калоража);
  - детерминизм: seed → воспроизводимый план, новый seed → новая неделя.
- **IngredientMatcher** — сопоставление продуктов холодильника с
  ингредиентами рецептов: нормализация (регистр/ё/пунктуация) +
  словарь из ~140 синонимов RU и EN («куриное филе» → chicken_breast);
  непознанные продукты не роняют генерацию, а попадают в предупреждения.
- **Архитектура провайдеров AI** (интерфейс `MealPlanner`):
  RuleBasedPlanner — по умолчанию и фолбэк; `LocalLlmPlanner` — каркас
  локальной LLM (Gemma/MediaPipe, подключение на Шаге 3) с прозрачным
  фолбэком на движок рецептов; интерфейс-заготовка `PlatformAiPlanner`
  под Android AICore / Apple Foundation Models. Качество и безопасность
  гарантированы слоем фильтров, а не моделью.
- **Схема БД v2 + миграция 1→2**: таблицы `meal_plans`, `planned_meals`
  (рецепты хранятся полными JSON-снимками — планы самодостаточны),
  `shopping_items` (чекбоксы покупок). Данные Шага 1 при миграции
  сохраняются — закреплено тестом.
- **PlanDao** и **PlanController**: генерация → сохранение → история →
  открытие → удаление, отметки «куплено»; контроллер уже подключён
  в `main.dart` (экран планера — Шаг 3).
- 129 тестов (было 24): матчер, калораж, целостность всей базы рецептов,
  интеграционные сценарии планера (аллергии/диеты/сроки/детерминизм),
  DAO планов, миграция схемы, PlanController.

### Приватность

- Вся генерация меню — локально; сеть по-прежнему не используется.

## [0.1.0] — 2026-10-24

### Добавлено (Шаг 1: архитектура + слой данных)

- Каркас Flutter-приложения (Material 3, нижняя навигация
  «Холодильник / Меню / Настройки»), светлая и тёмная темы
  с переключателем «системная/светлая/тёмная».
- Локализация RU + EN через `flutter gen-l10n`, переключение языка
  «системный / русский / english» в настройках.
- Локальная база SQLite (v1): таблицы `products` и `user_profile`,
  частично-уникальный индекс штрих-кодов, индексы под главный запрос
  холодильника; политика миграций на последующие шаги (docs/DATABASE.md).
- Модели `Product` (категории с типовыми сроками хранения, БЖУ на 100 г,
  статусы «активен/съеден/выброшен») и `UserProfile` (калораж, БЖУ, диеты,
  аллергии, приёмы пищи, регион для сезонности).
- DAO-слой: выборки «активные по возрастанию срока», «истекает ≤ N дней»,
  «просрочено», сводка-статистика; upsert-профиля с меткой онбординга.
- Логика свежести: зелёный / жёлтый (≤ 2 дней — под пуши ТЗ «за 1–2 дня»)
  / красный, даты сравниваются по календарному дню.
- Общая архитектура системы и контракт AI-планера (docs/ARCHITECTURE.md).
- 24 юнит-теста слоя данных и логики свежести (sqflite_common_ffi, хост).
- CI: `flutter analyze --fatal-infos` + `flutter test --coverage`.

### Решения по приватности

- `android:allowBackup="false"` — данные не уходят в облачные резервные
  копии Google; всё хранится только в приватной папке приложения.
- Сеть не используется на этом этапе; будущие обращения — только
  к открытому API Open Food Facts по действию пользователя.
