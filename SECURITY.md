# Security Policy — Безопасность

## Модель безопасности приложения

**Умный Холодильник & Шеф-Планер** — приложение без серверной части,
без аутентификации и без аналитики:

- Все данные (продукты, профиль питания) хранятся только в локальной базе
  SQLite в приватной папке приложения на устройстве.
- Резервные копии Google отключены (`android:allowBackup="false"`):
  данные не покидают устройство, включая облачные бэкапы и перенос.
- Сетевые запросы — только необязательные автопоиски, все выполняются
  прямо с устройства без серверов-посредников: (1) открытый API Open
  Food Facts — поиск по штрих-коду (передаётся только код продукта);
  (2) источник цены, выбранный в настройках: каталог Пятёрочки (поиск
  по названию; передаётся текст запроса и анонимный идентификатор
  устройства, генерируемый приложением), Kroger Public API (запросы
  с личными ключами самого пользователя, client_id/secret хранятся
  только на устройстве), Open Prices (по штрихкоду, без ключей),
  каталог Mercadona (Испания; кэш собирается на устройстве и хранится
  локально в SharedPreferences), поиск Aldi Süd (Германия; передаётся
  текст запроса) или Wegmans API (США; запросы с личным subscription-
  key пользователя, хранится только на устройстве).
  Никаких других запросов нет; найденное кэшируется локально.
- API-ключей в репозитории и в приложении нет и не будет: планировщик
  меню работает локально; ключи Kroger и Wegmans — только собственные
  ключи пользователя, вводимые им в настройках и хранимые локально.
- Секреты CI — только в GitHub Secrets репозитория, в git не попадают.
- Статический анализ безопасности: GitHub CodeQL (code scanning) проверяет
  собственные воркфлоу Actions на скрипт-инъекции и опасные триггеры
  (`.github/workflows/codeql.yaml`, еженедельно). Dart-код CodeQL не
  поддерживает — он статически проверяется `flutter analyze --fatal-infos`
  в CI; SQL-запросы DAO — только через параметризованные `whereArgs`.

## Что считается уязвимостью

- Потеря или утечка пользовательских данных за пределы устройства.
- Инъекция в SQL-запросы DAO (все запросы — только через параметризованные
  `whereArgs`, сырая интерполяция строк в SQL запрещена).
- Некорректная обработка внешних данных (штрих-код, ответ Open Food Facts,
  ответ источника цен — Пятёрочка/Kroger/Open Prices/Mercadona/Aldi
  Süd/Wegmans, OCR-текст чека)
  с исполнением или искажением данных.
- Обход запрета сети: любые запросы, не согласованные в README.

## Как сообщить

- Откройте **Security Advisory** через вкладку «Security» репозитория —
  приватный канал, без публичного раскрытия деталей.
- Либо заведите issue без чувствительных деталей и уточните в Advisory.

Ответ — в течение 7 дней. Исправления выходят отдельным релизом
с записью в CHANGELOG.md; кредиты исследователю — по желанию автора отчёта.
